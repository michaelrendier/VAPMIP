## Phase 47: The Child in C — `ptol.c` and `monad_harness.c`, and the Parity Tests (2026-11-25)

*Claude Sonnet 5.5, at Cody's direction: the Monad is built and tested in Python first; the C harness and `ptol.c` are ported after and always C; Python and C talk through a chat window, straight text.*

---

### The phase

The Monad of Phases 44–46 is ported to C. `monad_harness.c` is the **ears** (numbers, usage, drift, the speaker's state); `ptol.c` (section *The child's voice*) is the **voice** (window, `Tone7`, imitation, strut revisit, Lyndon verb group, tense plan, scaled orbweaver, `cam_encode`). `ptol -w` answers the console's `say` and `cmd` frames with the child (`/legacy <text>` keeps the earlier voice); `ptol -chat` is the same in a terminal; `ptol -turn` is one turn from the shell; `ptol -P` is the probe the tests drive. Commands: `/state /drift /plan /trace /audit /tense`.

### Data

`user_state.bin` (the usage ridge: 45,448 TF-IDF 1–2-gram features × 14 poles, gain, base, spread) and `voice_lex.bin` (77,477 WordNet words: parts of speech, first-synset 19 counts), both generated by `PtolC/tools/export_c_monad_data.py` (+ `splice_c_data.py`, which writes the irregular-verb table and the `cam_encode` word sets between `BEGIN/END GENERATED` markers inside the C files); gitignored like the other `.bin`. The directory override is `PTOLC_DIR` (not `PTOL_DIR`, which Cody's environment already sets to PtolC).

### The finding that needed a new file

`monad3_c.bin` keeps one lossy entry per word: "dog" is stored as a verb, "rules" is absent. With it, the C orbweaver plan differed from the Python on four of five test prompts. `voice_lex.bin` (all parts of speech per word, direct senses only, morphy by rule) fixed it; a first export that included morphy-derived senses made "roots" a verb lemma and was corrected the same day.

### The parity tests (`tests/test_c_parity.py`, 13)

Numbers (4,000 random strings and a fixed set, exact); the drift (300 steps); the usage meter, solution and repass (8 prompts); usage counts and p_word; verb groups (15 tenses × 460 verbs × number × person, exact); tense plan and mirror; `cam_encode` (1e-9); the bigram (1e-12); the orbweaver plan on first senses; the resident frame link with a scripted console. They found: a number-scanner backtracking error (the decimal option was tried without the no-decimal fallback), a one-character truncation before counting (`o + 2 < outsz`), a `tolower(*p++)` macro that skipped letters, and an overlapping `snprintf` that emptied a word.

### Differences from Python (not hidden; `PtolC/docs/CHILD_VOICE.md`)

The C meter is the usage ridge only; the C reads the first synset, not a sense; neighbours come from the co-occurrence matrix; connectives rotate in a fixed order; the prior under the speaker's usage is the corpus unigram, not Brown; ASCII-only tokenisers.

### Measured

188 tests passed. The C turn is fast (a few milliseconds on the laptop); the replies are child-grade ("the stone mixes the sculptor"), and a pivot at the deepest loop can repeat the same sentence. `docs/flowcharts/` holds the two code flow charts (ISO 5807 symbols; names checked against the C by `tests/test_flowcharts.py`).
